# Настройка Google Sheets exporter

Экспорт опционален. `demo`, `run`, `validate`, CSV/JSON и unit-тесты не используют
Google credentials. Live scraping и расписания отсутствуют.

## Подготовка собственной демонстрационной таблицы

1. Создайте свой Google Cloud project и включите **Google Sheets API**.
2. В IAM & Admin → Service Accounts создайте отдельный service account. Для доступа
   к таблице ему не нужны роли владельца/редактора всего Cloud project.
3. Если политика проекта разрешает ключи, создайте ключ service account и сохраните
   локальный credentials-файл **вне репозитория**. Не отправляйте его в Git, логи,
   сообщения или отчёты. Не используйте прежние рабочие аккаунты и ресурсы.
4. Откройте только собственную демонстрационную таблицу, указанную для этого проекта.
   Предоставьте email service account доступ **Editor** через Share.
5. Подготовьте листы с точными именами `subnets`, `metadata`, `validator_metrics`,
   `run_status`. Экспортёр не создаёт и не исправляет основные листы автоматически.
   Листы данных полностью принадлежат экспортёру: после публикации прежние значения
   заменяются, в том числе лишние строки. Не размещайте там собственные вычисления.
6. В первую строку каждого листа вставьте точные заголовки из следующего раздела.
   Оставьте свободные строки в `run_status` (например, 1000 строк). Заголовки должны
   быть обычным текстом. Дополнительные непустые колонки блокируют публикацию.

Используется единственный scope `https://www.googleapis.com/auth/spreadsheets`;
Drive API не используется. Scope не ограничивается одним файлом, поэтому нужны
отдельный service account, минимальный Share и проверка allowlist в приложении.

## Заголовки

Каждая строка ниже содержит названия колонок в требуемом порядке. При вставке в
Sheets можно разделить текст по запятой (Data → Split text to columns).

**subnets**

```text
netuid,collected_at_utc,subnet_name,emission,price,market_cap,volume_24h,liquidity,root_proportion,sentiment,price_change_1h,price_change_24h,price_change_1w,price_change_1m
```

**metadata**

```text
netuid,collected_at_utc,subnet_name,registration_date,network_key,discord_url,github_url,registration_cost
```

**validator_metrics**

```text
netuid,collected_at_utc,vtrust_avg,incentive_orange_max,incentive_orange_min,incentive_green_max,incentive_green_min
```

**run_status**

```text
run_id,started_at_utc,finished_at_utc,status,subnets_count,metadata_count,validator_metrics_count,error_summary,data_sha256
```

Девятая колонка `data_sha256` нужна для проверки повторного `run_id`.

## Windows PowerShell launcher

Из корня репозитория, после установки Python 3.10+ с Windows launcher `py`:

```powershell
py --version
py -m pip install -e .
.\scripts\publish_sheets.ps1
.\scripts\publish_sheets.ps1 -InputPath '.\src\taostats_pipeline\fixtures'
```

Без `-Apply` всегда передаётся `--dry-run`: конфигурация, Google extra, ключ,
RunId и переменные Google не нужны; даже переданный ConfigPath не читается.
Относительный InputPath разрешается относительно корня репозитория, а не текущего
каталога. Пробелы в путях поддерживаются; указывайте пути в кавычках.
Обёртка предпочитает только `py`, без молчаливого выбора другого Python.
Если `py --version` не работает, установите/исправьте Windows launcher. Установите
пакет в тот interpreter, который выбирает `py` (при необходимости активируйте venv).

Для apply установите `py -m pip install -e '.[google]'`. Создайте JSON в личном
локальном каталоге **вне checkout**, например через редактор (сохраните как UTF-8).
Выберите путь локально; не добавляйте конфигурацию или ключ в Git.
Формат содержит ровно два строковых поля:

```json
{
  "spreadsheet_id": "<ID собственной демонстрационной таблицы>",
  "credentials_file": "<абсолютный путь к собственному JSON-ключу вне репозитория>"
}
```

Это placeholders, замените их только в локальном файле. В JSON обратные слэши
Windows удваиваются (`\\`), либо используйте `/`. Ключ должен существовать;
обёртка проверяет только метаданные файла, не читает и не печатает его содержимое.
Конфигурация и ключ должны иметь абсолютные пути, без symlink/junction в любом
компоненте. Ограничьте доступ к ним своим пользователем средствами Windows.
`publish-sheets.local.json` дополнительно игнорируется Git, но всё равно должен
находиться вне репозитория. Другие произвольные имена конфигурации Git не скрывает.

Allowlist задаётся **отдельно от JSON**, после ручной проверки разрешённой таблицы:

```powershell
$configPath = Read-Host 'Абсолютный путь к локальной конфигурации вне репозитория'
$env:GOOGLE_ALLOWED_SPREADSHEET_ID = Read-Host 'Отдельно проверенный разрешённый ID'
.\scripts\publish_sheets.ps1 -Apply -ConfigPath $configPath -RunId demo-001
```

Введите ровно `PUBLISH demo-001` при запросе. Регистр и пробелы значимы;
`Y`, пустой ввод и невозможность интерактивного чтения блокируют запуск публикации.
RunId обязателен только для apply: 1–128 ASCII букв, цифр, `_` или `-`.
Он не генерируется автоматически. Не храните разрешённый ID в общих профилях,
отслеживаемых файлах или сценариях. Обёртка не копирует целевой ID в allowlist:
сначала проверяет точное совпадение с независимо заданным значением.

PowerShell `$env:NAME` задаёт переменную текущего процесса и его будущих дочерних
процессов; обычная `$NAME` не становится environment variable. `.env` не загружается.
Для дочернего Python обёртка временно устанавливает три Google-переменные, затем
в `finally` восстанавливает их прежние значения. После работы можно убрать
allowlist: `Remove-Item Env:GOOGLE_ALLOWED_SPREADSHEET_ID -ErrorAction SilentlyContinue`.
Не печатайте окружение и не включайте трассировку PowerShell/transcript с секретами.

Основной способ запуска — обычный `.\scripts\publish_sheets.ps1`, без
`ExecutionPolicy Bypass`. Не меняйте глобальную ExecutionPolicy. Если действующая
политика запрещает запуск, используйте согласованный с владельцем компьютера способ
разрешения/подписания локального скрипта; обход политики не является стандартным
решением. Организационную Group Policy обходить не следует. Scheduled tasks не нужны.

Обёртка вызывает Python publish ровно один раз, передаёт его exit code и не
повторяет apply после ошибки/timeout. Собственные отказы обёртки возвращают 1.
Если процесс прерван или исход неопределён, сначала вручную проверьте `run_status`,
данные и staging по разделу восстановления ниже. Не создавайте новый RunId ради
слепого повтора. Новый явный запуск требует нового интерактивного подтверждения;
гарантии существующего exporter и ограничения одного писателя остаются прежними.
Прямой Python CLI по-прежнему доступен и не имеет интерактивной защиты обёртки.

Offline-проверки: `py tests/launcher_checks.py` (или Python из venv).
Нужен PowerShell 5.1 либо 7; Pester и новые зависимости не нужны. Тесты создают
только временные синтетические файлы, подменяют Python launcher и ввод подтверждения,
проверяют dry-run, отказы, аргументы с пробелами, exit code и отсутствие повторов.
Тестовый дочерний shell использует process-only `-ExecutionPolicy Bypass`; политика
пользователя и компьютера не меняется. Если Group Policy запрещает запуск,
проверки завершатся ошибкой, а не будут считаться успешными отказами обёртки.
Linux job допускает skip при отсутствии PowerShell. Отдельный обязательный Windows
job запускает stdlib runner на Windows PowerShell 5.1 и PowerShell 7 с
`--require-powershell`: отсутствие executable, нулевое число тестов или пропуск
всего набора завершаются ошибкой. Google credentials и API не используются.
Негативные тесты проверяют дубли JSON-полей (включая escaped-имена), неверные типы,
пустые значения и настоящий отказ Read-Host в неинтерактивном shell; во всех
этих случаях Python publish не вызывается. JSON читается как UTF-8 с BOM и без BOM,
а до ConvertFrom-Json проверяется схема из двух уникальных строковых полей,
чтобы поведение при дублях не зависело от версии PowerShell.
Для выбора shell используйте
`$env:LAUNCHER_TEST_SHELL = (Get-Command powershell).Source` или путь к `pwsh`.

Отдельный локальный smoke-test с настоящим `py.exe`, строго dry-run, после
установки пакета в выбираемый им Python:

```powershell
# Из корня репозитория; без ConfigPath, RunId, Google credentials и -Apply.
& .\scripts\publish_sheets.ps1
$LASTEXITCODE
# Отдельная проверка CLI с настоящим executable, без обёртки и подмен:
py.exe -m taostats_pipeline publish-sheets --input .\src\taostats_pipeline\fixtures --dry-run
```

Обёртка сама ищет executable `py` и вызывает `py --version`, затем `py -m ...
--dry-run` на синтетических fixtures. Ожидаются exit code 0, `status: dry_run`
и `remote_structure_checked: false`. Если `py` не находит установленный Python,
исправьте его установку/выбор interpreter; реальную публикацию для проверки не запускайте.

## Прямой Python CLI и переменные окружения

Для offline dry-run достаточно обычной установки. Для явной публикации:

```powershell
python -m pip install -e '.[google]'
$env:GOOGLE_SPREADSHEET_ID = '<ID вашей разрешённой демонстрационной таблицы>'
$env:GOOGLE_ALLOWED_SPREADSHEET_ID = '<тот же ID, подтверждённый отдельно>'
$env:GOOGLE_CREDENTIALS_FILE = 'C:\private\service-account.json'
```

Не копируйте placeholders буквально. ID берётся из URL собственной таблицы между
`/d/` и `/edit`; не используйте URL целиком. Две переменные ID должны совпадать
**точно**, без пробелов. Проверка повторяется перед каждой записью, включая retries.
Разрешённый ID задаёт оператор: это защита от ошибочного выбора, а не от изменения
обеих переменных злоумышленником. `.env.example` — образец; CLI не загружает `.env`.
Не меняйте существующие GitHub Secrets ради локальной настройки.

## Dry-run и публикация

```powershell
python -m taostats_pipeline publish-sheets --input ./src/taostats_pipeline/fixtures --dry-run
# Эквивалентно: без обоих флагов также только dry-run.
python -m taostats_pipeline publish-sheets --input ./src/taostats_pipeline/fixtures
# Только после локальной проверки и подготовки таблицы:
python -m taostats_pipeline publish-sheets --input ./src/taostats_pipeline/fixtures --apply --run-id demo-001
```

`--apply` и `--dry-run` взаимоисключающие. Dry-run разбирает manifest, проверяет
модели и сериализацию, не импортирует Google client и не обращается к сети.
`remote_structure_checked: false` означает, что доступ и удалённые заголовки ещё
не проверены. Для этого нужен `--apply`; он сначала читает и проверяет структуру,
затем начинает запись. `--strict` / `--no-strict` работают как в других командах.

Числа и ID передаются **текстом**: Decimal в фиксированной десятичной записи,
`None` как пустая ячейка, UTC как ISO-строка. `RAW` и явный `stringValue` сохраняют
точность и оставляют `=...`, `+...`, URL и даты буквальным текстом. Для вычислений
в Sheets потребуется явное преобразование в число с учётом локали.

Проверка запрашивает `majorDimension=ROWS` и `UNFORMATTED_VALUE`. В этом режиме
[ValueRange](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values?hl=en)
может содержать JSON-числа, строки и boolean; пустые хвостовые ячейки/строки опускаются.
Наш протокол принимает **только строки**: число `7` не равно строке `"7"`, а `"1.0"`
не равно `"1"`. Числа, boolean и null после нашей записи означают несоответствие формату,
а не повод молча преобразовать значение. Обрезанные хвостовые ячейки дополняются `""`,
полностью пустые хвостовые строки игнорируются; внутренние пустые строки сохраняются.
Непустые лишние строки/колонки, пропущенные записи и отличия текста блокируют успех.
Читается весь лист, поэтому старые значения за пределами нового набора тоже проверяются.

## Проверка результата и восстановление

CLI выводит JSON и возвращает 0 только для dry-run, проверенного успеха или
подтверждённого ранее успешного `run_id`. `failed` и `partial` возвращают 1.
Сверьте `run_id`, UTC-время, три счётчика, `status`, `error_summary` и `data_sha256`
в `run_status`. Не считайте один только exit code доказательством отсутствия записи:
при сетевой ошибке сервер мог уже применить финальный запрос.

- `failed`: ошибка до финального запроса. Старые данные сохранены; staging может
  остаться. Если структура/credentials не подтверждены, удалённого журнала не будет.
- `partial`: финальный запрос уже пытались выполнить, но результат не подтверждён,
  данные не совпали либо обнаружены конкурентные изменения. `verification: mismatch`
  означает подтверждённое несоответствие формата/данных; `unavailable` — невозможность
  проверки из-за API/клиента, `journal_mismatch` — журнал не подтверждает наш batch,
  `structure_changed` — изменились ID, имена или размеры листов. Это разные причины;
  `partial` сам по себе не доказывает смесь листов или повреждение данных.
- `success` записывается вместе с тремя наборами в финальном batch, после проверки
  staging. После этого CLI читает журнал и все основные листы, повторно проверяет
  структуру и только затем возвращает `success`, `verification: matched`,
  `current_data_status: matches`. Подтверждённое несоответствие данных приводит
  к попытке заменить запись журнала на `partial`; недоступность API при проверке
  **не** перезаписывает потенциально корректный `success`.

Cleanup отделён от публикации: если данные и журнал подтверждены, ошибка удаления
staging оставляет **`status: success` и exit code 0**. JSON содержит `cleanup_warning`
и `staging_sheet_ids` для ручной проверки; удалённый `success` не меняется.
Потеря ответа cleanup также даёт предупреждение: листы могли уже удалиться.
Изменение/удаление staging другим процессом после финального batch относится к cleanup;
перед удалением проверяется, что ID, имена и размеры staging всё ещё совпадают.

При потере ответа финальный batch **не повторяется вслепую**. Выполняется чтение
журнала и данных: если они совпадают, операция признаётся завершённой. Если прочитать
результат нельзя, CLI сообщает `partial` и не перезаписывает потенциально успешную
строку. Если журнал прочитан, а основные листы проверить не удалось, остаются
`partial`, `verification: unavailable`, `current_data_status: unverified`, без
перезаписи удалённого `success`. Даже запись ошибки в журнал при недоступном API
не гарантируется.

Повторный `run_id` с тем же SHA и единственной строкой `success` возвращает
`status: already_published`, `already_published: true`, `historical_status: success`
без записей, с exit code 0 (успешный no-op). Это **не новый `success`** и не утверждение,
что старый запуск остаётся текущим. Содержимое трёх листов сравнивается с входом:
`current_data_status: matches` означает совпадение прочитанных значений, `differs` —
они отличаются (например, опубликован следующий запуск). Совпадение не доказывает,
что именно старый запуск был последним: следующий мог записать те же данные.
При ошибке чтения проверка завершается ненулевым кодом без записи.
Другой SHA, дубликаты, `failed` или `partial`
блокируют повторное использование ID; после проверки причин используйте новый ID.
Не удаляйте строки журнала ради автоматического повтора неопределённой операции.

Запускайте **только один публикующий процесс** и исключите ручные изменения во время
публикации. Непосредственно перед финальным batch повторно проверяются ID, имена,
типы и размеры основных/staging-листов, заголовки, исходные данные и журнал.
Обнаруженное изменение останавливает публикацию без финального batch и записи
в устаревшую строку журнала. После batch структура основных листов и журнал
проверяются до/после проверки данных. Обнаруженные изменения дают `partial` без
слепого повтора и отката. Запись статуса ошибки также проверяет принадлежность
строки журнала перед перезаписью.

Эти проверки **не являются блокировкой**: между последней проверкой и запросом,
между чтениями, а также после успешного возврата возможны новые изменения.
В частности, конкурентное изменение размера перед запросом расширения может
конфликтовать с его рассчитанным размером; rename/recreate может изменить адресацию.
Если изменение обнаружено уже после batch, данные могли быть записаны. Нет
распределённой блокировки, compare-and-swap или гарантии exactly-once между процессами.
После сбоя могут остаться скрытые `_stage_*` листы:
сверьте указанные в отчёте `staging_sheet_ids`, покажите нужные листы и удалите вручную
после проверки результата. Автоматической очистки чужих или старых staging нет.

## Типичные ошибки

| Ошибка | Действие |
| --- | --- |
| Invalid GOOGLE_SPREADSHEET_ID | Задайте ID, а не URL, без пробелов |
| Spreadsheet allowlist mismatch | Сверьте обе переменные с разрешённой таблицей |
| GOOGLE_CREDENTIALS_FILE missing | Проверьте путь и права чтения локального файла |
| Client initialization failed | Установите extra `google`, проверьте service account |
| 401 / 403 | Проверьте ключ, Sheets API и Share; автоматических retries нет |
| Required sheet names / Header mismatch | Исправьте имена и заголовки вручную |
| run_status grid is full | Добавьте пустые строки вручную |
| Input validation failed | Исправьте manifest/HTML или типы/полноту моделей |
| 429 / 5xx | Чтения и RAW update повторяются до 3 попыток с backoff 0.25/0.5 с |
| Final publication outcome unresolved | Проверьте журнал и данные перед новым запуском |

Создание/удаление листов, финальный batch и запись журнала автоматически не
повторяются: их неопределённый исход требует проверки. API-ответы и исключения
авторизации редактируются до безопасных категорий; содержимое credentials не выводится.

Атомарность относится только к операциям одного финального
[`spreadsheets.batchUpdate`](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate).
Staging, проверки и очистка — отдельные запросы; весь процесс не является транзакцией.
Google отдельно предупреждает о влиянии конкурентных изменений соавторов.
