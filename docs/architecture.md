# План архитектуры

Это план следующих этапов, а не описание реализованного pipeline.
Сейчас сбор, парсинг и Google Sheets смешаны в трёх скриптах `src/`.
На первом этапе они остаются неизменными; автоматический запуск из этой ветки удалён.

## Будущие слои

| Слой | Вход → выход | Ответственность |
| --- | --- | --- |
| Сбор данных | Разрешённый URL → HTML + время | Таймауты, лимиты страниц, повторы; адаптер Playwright |
| Парсинг | HTML → записи | Чистые функции без сети, браузера, окружения и экспорта |
| Валидация | Записи → проверенные записи + ошибки | Схема, типы, диапазоны, обязательные поля, дубликаты subnet_id |
| Экспорт | Проверенные записи → результат записи | Локальный файл по умолчанию; Google Sheets включается явно |
| Журнал запусков | События → статус запуска | run_id, время, счётчики, ошибки без секретов и полного HTML |

Поток: сбор → парсинг → валидация → экспорт. Каждый этап сообщает результат
в журнал; ошибка валидации должна препятствовать внешней записи.

## Конфигурация и безопасность

Будущий загрузчик читает `GOOGLE_SPREADSHEET_ID`, `GOOGLE_CREDENTIALS_FILE` и имена
листов из `.env.example`. Реальной таблицы по умолчанию нет. Google-клиент создаётся
только после явного выбора экспорта и проверки конфигурации. Credentials вне Git.
Листы `subnets`, `metadata`, `validator_metrics`, `run_status` — планируемые назначения;
никакая таблица сейчас не создаётся и не подключается.

До включения внешних операций нужны локальный dry-run, тесты с поддельными клиентами,
отдельная тестовая таблица владельца проекта и явное разрешение записи.
Не переносить старые Secrets или ресурсы прежней команды. Определить стратегию
идемпотентной записи вместо безусловного clear/append. Не логировать ключи и токены.

## Этапы

1. Зафиксировать чистые функции синтетическими тестами (текущий PR).
2. Перенести парсинг в модули без побочных эффектов; заменить AST-мост прямыми
   импортами, сохранив тесты поведения. Расширить Ruff на новый код.
3. Ввести модели, валидацию и явную конфигурацию без рабочих значений.
4. Добавить сбор с ограничениями, локальный экспорт и журнал запусков.
5. Проверить Google-адаптер на mocks и отдельной тестовой таблице; только затем
   обсуждать запуск вручную или по расписанию. CI остаётся без внешних интеграций.

## Ограничения первого этапа

Тесты не проверяют живой HTML, пагинацию браузера, Google API и права доступа.
AST-мост исполняет только явно выбранные определения функций из локального исходника
с минимальными зависимостями; тела старых модулей не исполняются. Пустые строки
вместо отсутствующих полей — существующее поведение, не готовая политика валидации.
Удаление workflow в PR не отключает старые расписания на `main` до принятия изменений.
