# Taostats API v1: safe HTTP transport (PR #5C)

Модуль `taostats_pipeline.api_v1_transport` использует только стандартную
библиотеку Python. Он независим от HTML pipeline, CLI, моделей и Google Sheets.
Импорт, `Query`, `Budget`, `LiveAllowance`, создание limiter и сессии страниц
не открывают соединений и не читают credentials. Конструктор `Transport`
отказывает без `allow_live=True`; каждый `get` / `fetch_next_page` требует
собственного явного `allow_live=True`. Создание разрешённого транспорта только
собирает обработчики urllib, без сети и чтения ключа.

## Контракт и архитектура

- `Query`: только `page` (1..1 000 000), `limit` (1..200), опциональный `netuid`
  (0..65535) и boolean `validator_permit` только для metagraph. Boolean вместо
  integer, строки, произвольные query-параметры и URL не принимаются. Числовые
  границы — консервативная локальная политика, не подтверждённый контракт API.
  `urlencode` формирует query из проверенных значений.
- `Transport.get`: один GET и decoded JSON object. Проверка envelope отдельно.
  Единственный origin/base — `https://api.taostats.io/v1/`; аргумента base URL нет.
  Allowlist точно повторяет шесть endpoints исследовательского документа:
  `/v1/subnets/identities`, `/v1/subnets/metrics`, `/v1/subnets/pools`,
  `/v1/subnets/pools/aggregate`, `/v1/subnets/metagraph/aggregate`,
  `/v1/subnets/metagraph`. URL, query, fragment, trailing slash и иные пути
  вместо endpoint отклоняются до резервирования.
- Стандартная TLS-проверка urllib, environment proxies отключены, redirect handler
  запрещает переходы, включая переходы на тот же origin. Любой статус кроме 200
  отклоняется без чтения тела; конечный URL также должен точно совпадать.
- Ключ читается только из `TAOSTATS_API_KEY`, внутри разрешённого запроса после
  резервирования. Значение отправляется напрямую в `Authorization`, без Bearer.
  Ключ не является параметром конфигурации/CLI и не хранится на транспорте.
  Заголовок удаляется с временного `Request` при завершении. Google credentials
  нигде не используются. Непустой ключ должен состоять из печатных ASCII-символов
  без пробелов и управляющих символов; это защита заголовка, не проверка ключа.
- Timeout по умолчанию 20 секунд, разрешён integer 1..60. Размер ответа по
  умолчанию и максимум 1 MiB; читается не более лимита + одного контрольного байта.
  Требуется UTF-8 JSON object. Невалидный JSON, дубли ключей, NaN/Infinity,
  чрезмерные числовые значения и чрезмерная вложенность отклоняются.
  Дробные JSON-числа (включая экспоненциальную запись) разбираются напрямую
  в `Decimal`, без промежуточного float и потери исходной десятичной точности
  в рамках ограничений: литерал не длиннее 128 символов; явный показатель
  степени от -308 до 308 проверяется до создания Decimal; для ненулевого
  результата также ограничен десятичный порядок (`adjusted()`) от -308 до 308.
  Эти ограничения действуют на `parse_float`; JSON integer остаётся Python int.
- `TransportError` содержит только фиксированное сообщение. Исходные исключения
  urllib/декодера не передаются как cause/context. Нет логирования, полного URL,
  headers, тела ответа или ключа в диагностике. Нет автоматических retries даже
  для 429, timeout или 5xx; `Retry-After` не запускает ожидание и повтор.

## Бюджеты и страницы

`Budget` из `api_v1.py` общий для обычных GET и сессий страниц. Обычный GET
резервирует `reserve_request()`. `PageSession` владеет `PageMerger` с тем же
Budget и перед каждым HTTP-вызовом вызывает только `reserve_next_page()` —
это одна резервация запроса и страницы. Повторного списания в транспорте нет.
Полученный JSON передаётся в существующий `PageMerger.accept()`, использующий
`parse_envelope`; результат доступен только через `finish()` после всех страниц.
Фильтры в сессии фиксированы, page начинается с 1. Для остальных endpoints
нужно явно выбрать `key_fields` согласно семантике выборки.

Ошибка загрузки/валидации закрывает сессию: продолжение и частичный результат
запрещены. Отказ Budget происходит до ожидания limiter, чтения ключа и открытия
соединения. Резервации учитывают попытки и не возвращаются при ошибках, включая
отсутствующий ключ. Отдельный `LiveAllowance` резервируется первым, поэтому
отказ Budget может израсходовать разрешение live-операции без сетевого запроса.

`LiveAllowance(max_requests=1 или 2)` обязателен отдельно от Budget. Это явное
ограниченное разрешение малой live-операции, **не кредитный бюджет**. Один
allowance можно разделять между транспортами. Значения больше двух запрещены;
массового обхода/автопагинации нет. После исчерпания allowance следующая страница
не загружается, а неполная выборка не выдаётся. Нельзя автоматически создавать
новые allowance ради продолжения обхода. Для будущего массового сбора требуется
отдельное изменение с подтверждённой тарификацией, верхней оценкой кредитов,
явным разрешением расходов и условием остановки. Пока такой политики нет,
массовый live-сбор не разрешён. Даже один запрос может расходовать неизвестное
число кредитов; защита кредитного баланса не гарантируется.

## Локальные границы гарантий

`LocalRateLimiter` сериализует обращения и выдерживает интервал минимум 15 секунд
между началами вызовов HTTP в рамках одного экземпляра. Блокировка удерживается
на время HTTP; после долгого запроса накопленного burst нет. Один экземпляр
можно передать нескольким транспортам. По умолчанию у каждого транспорта свой
limiter. Это локальный запас относительно исходного ориентира 5 запросов/минуту,
а не подтверждение серверных правил квоты.

Ограничитель не координирует другие экземпляры, процессы, машины и клиентов
с тем же ключом. Budget не является межпроцессным или транзакционным счётчиком;
при совместном использовании Budget разными транспортами из разных потоков
вызывающая сторона должна сериализовать операции. Состояние лимитов не
сохраняется между запусками. Код внутри Python-процесса может создать новые
объекты или изменить private-состояние; это не sandbox для недоверенного кода.

Невозможно гарантировать кредитный баланс, полноту/атомарность серверных данных
или квоту аккаунта без подтверждённой тарификации и общей внешней координации.
Timeout urllib ограничивает блокирующие операции сокета, а не общее время запроса:
DNS, ожидание limiter и медленная передача могут увеличить полное время.
Ключ неизбежно существует в окружении и временной памяти HTTP-библиотеки;
дампы памяти, сторонняя трассировка/debug logging и отладчики вне контроля
модуля не защищены. Private opener предназначен только для поддельного HTTP
в offline unit tests; его замена снимает гарантии стандартного HTTP-обработчика.

## Проверка без сети

`tests/test_api_v1_transport.py` использует только синтетические ответы,
тестовый ключ-заглушку и управляемые часы. Общий `conftest.py` блокирует сеть и
дочерние процессы. Проверяются запрет live, отложенное чтение ключа, allowlist,
параметры, redirect chain urllib без сети, HTTP 401/429/500 и redirects,
timeout, безопасные ошибки, JSON/size limits, Budget, allowance, общий limiter,
пагинация без двойного списания и отказ после ошибок/исчерпания.
Реальные API-запросы и Google Sheets для проверки не нужны и не выполнялись.
